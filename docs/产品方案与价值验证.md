# 研证：投资判断验证助手

## 产品定义

帮助已有初步判断的个人投资者，将判断拆解为可检查的问题，通过金融数据寻找支持证据、相反证据和证据缺口，修正判断并继续研究。

产品的起点是用户的判断，而非一张指标表。用户可以来自自己的观察、外部观点或旧判断更新。例：“利润增长很快，所以盈利质量也在改善。”系统区分“利润增长”与“盈利质量”两个主张，检查增长指标和现金流匹配情况，避免单一支持数字被当作完整结论。

## 用户与任务

目标：具备基础投资知识、已有自选股、希望核对基本面判断的个人投资者。

三种场景：验证自己的观察、核对外部观点、用新报告更新旧判断。痛点假设：不知道该查哪些指标；只查支持证据；不理解矛盾数据；不知道下一步补什么。尚无访谈证明普遍程度，不使用虚构调研或市场规模。

核心成功任务：用户在一次会话中确认检查问题，获取可追溯数据，识别支持与相反方向，留下一条修正判断或待研究问题。

## 首版范围

非金融类A股，增长与盈利、利润与现金匹配、回款效率三条检查路径。采用扶摇财务指标接口，比较相邻年份同类报告。判断拆解、查询、计算、证据展开、追问、记录、导出完成闭环。

非目标：买卖建议、股价预测、全面投资评级、经营原因、竞争优势、海外业务或估值合理性。跨报告类型比较、金融公司特殊口径、自动最新报告检测和定时监控不在首版范围。

## AI Native的增量价值与边界

用户用自然语言表达并可能混合多个判断；LLM将其映射为明确路径，指出不支持部分，用户确认后再查询。追问可以形成新的检查计划。程序完成标准化计算，模型解释围绕现有证据，不自行生成数字。

固定问题确实可用规则与表格解决，因此不能只凭使用LLM就宣称必要性。待验证的增量价值为：复杂表述匹配、混合意图拆解、范围外识别与下一步问题组织。受控Agent只在有限工具与路径范围内工作，不提供多Agent或自由自主研究。

## 工作流与状态

输入判断 → 计划待确认 → 人工修改检查路径 → 获取两期数据 → 计算与方向检查 → 可追溯证据 → 用户复核 → 保存或再检查。

金融接口失败：停止并展示错误。部分字段缺失：保留可用数据并显示不可判断部分。LLM结构不合规：拒绝执行计划。AI解读失败：保留确定性结果并明示。没有配置：真实模式不自动回退演示。

支持证据不证明投资逻辑成立，相反方向不等于推荐卖出。零变化不会被写成改善。利润符号、低基数、季节性、一次性项目需进一步核对。

## 如何证明价值

当前已有工程测试与用户提供的单案例真实链路证据，尚没有用户效率对照证据。按三层验证：

1. **工程可用性**：计划schema、同类期间、字段追溯、计算、异常处理；程序和mock测试有实际记录。
2. **真实工具可靠性**：拿到凭据后，对至少3个非金融标的实测两期接口；与原始响应逐项对照。完成标准：展示值一致、缺失明确、计算可复现。随后验证LLM能生成合规计划与带证据解释。
3. **用户任务价值**：邀请3—5位有阅读财务数据经历的用户，完成同一组任务。比较人工查数、普通AI回答与研证。顺序交叉安排，减少熟悉任务的影响。

任务集至少10项，包含三类问题、混合意图、模糊期间、股价预测、信息不足和相反证据。指标：任务完成时间中位数、意图匹配正确数/总数、数值一致数/总数、有效引用数/应引用数、成功完成数/总数、找到关键反例人数/参与人数。记录操作步骤与误解，不把满意度单独当作成功。

目标暂定：事实展示值与源值一致率100%；事实引用覆盖100%；重要接口错误不被掩盖；用户任务时间较人工基线减少。时间改善幅度应由实测报告，不预先编造。

如果仅固定问题表现好，而开放表述没有增量，应加强模板式检查并承认LLM贡献有限。如果用户无法理解比率和证据，调整解释与证据呈现，而非扩展模块。

## 数据与安全

只用题目提供的扶摇，不依赖额外付费数据、公告原文或财报上传。真实Key不进入源码、Git、记录或导出。会话配置刷新清除；服务器配置通过安全环境变量。判断会传至用户选择的模型服务，不输入身份、真实持仓与受限材料。演示公司与数据均为构造，无收益承诺。
